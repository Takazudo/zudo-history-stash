The exact decimal column is checked against every finite numeric export from the built Core package.
Human-readable units do not replace those bytes, characters, items, milliseconds, or days.

The storage threshold and diff input limit currently share the same numeric value but are separate
contracts. Similarly, byte limits measure encoded bytes while the idempotency key limit counts
characters; callers must apply the named boundary, not match a coincidental number.

## Worker binary settings

The deployed Worker publishes these settings through `GET /v1/capabilities`. Values below are the
production and preview defaults; a deployment may inject different positive safe integers only when
all invariants hold. They count exact content bytes, not JSON or protocol framing.

| Setting | Default | Meaning |
| --- | ---: | --- |
| `JSON_INLINE_MAX_BYTES` | `5000000` | Text content may be returned inline by JSON-compatible reads; change set/import schemas remain text-only. |
| `D1_INLINE_MAX_BYTES` | `524288` | Maximum default size eligible for D1-inline placement. |
| `HTTP_REQUEST_MAX_BYTES` | `100000000` | Operator-declared raw request/content ceiling; not runtime Cloudflare-plan discovery. |
| `SINGLE_UPLOAD_MAX_BYTES` | `33554432` | Maximum raw single-upload content (32 MiB). |
| `MAX_FILE_BYTES` | `100000000` | Maximum declared file size for single or multipart upload. |
| `DIFF_MAX_BYTES` | `524288` | Maximum bytes on each side of a text diff. |
| `MULTIPART_PART_BYTES` | `8388608` | Multipart part size (8 MiB). |
| `MAX_OPEN_UPLOAD_SESSIONS` | `8` | Open sessions per stash. |
| `MAX_RESERVED_UPLOAD_BYTES` | `500000000` | Aggregate reserved upload bytes per stash. |
| `UPLOAD_SESSION_TTL_SECONDS` | `86400` | Upload-session lifetime (1 day). |

The settings do not infer one another: representation (`text`/`binary`), content access
(`inline`/`raw`/`deleted`), transfer (`json`/`single`/`multipart`), storage (`d1`/`r2`), and diff
eligibility are independent. Above 5,000,000 bytes does not imply `binary`; valid UTF-8 remains
`text` at any supported size. D1 inline is capped at `1,500,000`, `MAX_FILE_BYTES` at
`1,073,741,824` (1 GiB), and `MAX_FILE_BYTES / MULTIPART_PART_BYTES` rounds up to at most 10,000
parts. `MAX_RESERVED_UPLOAD_BYTES` must be at least `MAX_FILE_BYTES`; production multipart parts
must be at least 5 MiB; and `UPLOAD_SESSION_TTL_SECONDS` must be at most 31,536,000. 1 GiB is a
configurable correctness ceiling, not a performance certification. Tests inject small thresholds
and never allocate a 1 GiB body.
