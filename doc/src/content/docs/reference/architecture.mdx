Consumers call Stash through HTTP/fetch or a Cloudflare RPC binding, normally through the
[Client package](./client-package.mdx). The Viewer uses the same API through its proxy or binding.
D1 owns metadata and mutable heads; large immutable bytes can spill into a private R2 bucket.

## Data relationships

| Data | Role |
| --- | --- |
| `stashes` | Lifecycle and descriptive metadata for one namespace. |
| `tokens` | Credential hashes, scope, expiry, revocation, and rotation metadata; never recoverable secrets. |
| `blobs` | Content-addressed text/binary metadata and the inline-or-R2 storage reference. |
| `files` | The mutable head for each stash/path pair. |
| `commits` | One durable, sealed verdict for every successful write unit. |
| `versions` | Append-only history; every row has a required commit ID, and its database-global ID is also the change cursor. |
| `change_sets`, `change_set_entries` | Immutable, expiring review candidates and their decision state. |
| `idempotency` | Request-identity ledger for safe write replay. |
| `gc_jobs`, `gc_runs` | Generation-fenced garbage-collection leases, progress, and results. |

Representation (`text`/`binary`), content access (`inline`/`raw`/`deleted`), transfer
(`json`/`single`/`multipart`), storage (`d1`/`r2`), and diff eligibility are separate contracts.
Above 5,000,000 bytes does not imply binary; valid UTF-8 remains text at any supported size. D1
inline, raw streaming, and the 524,288-byte-per-side diff bound are independent choices.

## Write protocol

1. Validate authorization, entry shapes and limits, and prepare any immutable R2 objects before the
   database batch.
2. Insert one unsealed commit row through an aggregate gate that checks every path fence and the
   optional whole-stash cursor together.
3. Make every blob, version, and head statement conditional on `EXISTS` of that gate row and repeat
   its own per-path fence. Each appended version receives the commit ID; the head mutation follows
   its version.
4. Run the seal `UPDATE` last. It records the entry/change counts and first/last change IDs. Exactly
   `meta.changes === 1` on this statement is the sole success verdict.
5. After the sealed batch succeeds, publish the commit's ordered advisory live-event frames.

The seal is last because D1 batch statements cannot use an earlier statement's metadata as a SQL
predicate. A table check makes an incomplete seal throw and rolls the entire batch back. Code
collects change IDs by querying rows with the commit ID; per-statement `last_row_id` is not a reliable
source because a zero-row fenced insert can retain a stale value.

This protocol makes commits all-or-none. A failed entry fence exposes only the failed entries in
root-level `conflicts[]`; exactly one failure whose `current` is `null` is `404 not-found`, and every
other commit entry-fence failure is `409 commit-conflict`. On commit creation, a whole-stash fence
failure is `409 stale` without per-entry conflicts. No commit, version, or head from the attempt
remains visible. Consumers must refresh and decide how to rebuild the entire operation. Approval
uses the same aggregate fence and never rebases a candidate; for approval specifically, one missing
`delete` target is `404 not-found`, while other entry conflicts are `409 commit-conflict`.

Single-path create, update, delete, rollback, import, and upload completion are uniform one-entry
commits, so every version has a non-null commit ID. `skipIfUnchanged` and unchanged upload completion
append no version and mint no commit. A rollback or commit revert appends new versions—it never moves
history backward. If a fence loses after an R2 upload, the object can remain unreferenced until
garbage collection, but it never becomes a file head.

An idempotency key identifies one canonical request. Reusing the key with changed content is a
`422 idempotency-key-reused` error, not permission to change a replayed operation.

## Lifecycle and recovery

Stash deletion is soft and deferred. It revokes active stash credentials; restoration retains data
but does not revive those credentials. Garbage collection uses generation-fenced leases so an
expired runner cannot finalize or release a successor's work, and every bounded run is recorded.

Live delivery subscribes before replay, then emits advisory events. A consumer must reconcile with
the authoritative change feed and resource reads after `ready`, `change`, `commit`, `change-set`, or
reconnect; the event stream is not a second source of truth.
