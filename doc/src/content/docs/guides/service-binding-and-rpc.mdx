A same-account Cloudflare Worker can reach the Stash Worker without using its public route. The
public client supports two authenticated binding shapes: an HTTP fetch binding and the named
`StashRpc` entrypoint. The consuming Worker must use compatibility date `2024-04-03` or later for
Worker RPC.

## Fetch service binding

Bind the Stash service to the consumer and pass its `fetch` method to the SDK. The base URL only
needs to be a syntactically valid, inert HTTPS origin because the binding performs the internal
dispatch. Authentication is still mandatory.

{/* zhs-example: consumer-fetch-binding */}

```ts
import { createStashClient } from "@takazudo/zudo-history-stash";

export interface StashFetchBinding {
  fetch(input: RequestInfo | URL, init?: RequestInit): Promise<Response>;
}

export function createFetchBindingClient(input: { binding: StashFetchBinding; token: string }) {
  return createStashClient({
    baseUrl: "https://stash.internal",
    token: input.token,
    fetch: (request, init) => input.binding.fetch(request, init),
  });
}
```

## Named RPC entrypoint

For the typed alternative, configure a service binding whose entrypoint is `StashRpc`, type it as
`StashRpcEntrypoint`, and select the SDK's discriminated RPC transport. Business responses remain
`ClientResult` unions. If the outer binding call rejects before a response exists, the SDK throws
`StashHttpError` with `status === 0`; direct calls on the binding also need an outer rejection
boundary.

RPC raises neither the platform nor API limits. Cloudflare's outer serialized RPC value payload is
capped at 32 MiB, including envelope overhead, so an application value of exactly 33,554,432 bytes
is not guaranteed to reach dispatch. A `Request` or `Response` sent through the flow-controlled
`requestStream()` bridge is RPC-aware: its body stream is not serialized into that value payload.
The SDK selects this bridge for raw, capabilities, and upload routes when the binding exposes it.
That transport boundary is independent from Stash's content policy:
the compatibility JSON/proposal/import path is text-only with a 5,000,000 UTF-8-byte body rule,
while raw uploads preserve either text or binary and use the capability settings
(`HTTP_REQUEST_MAX_BYTES=100000000`, `SINGLE_UPLOAD_MAX_BYTES=33554432`, and multipart above the
single limit). Above 5,000,000 bytes does not imply binary; valid UTF-8 remains text. Representation,
content access, transfer, storage tier, and diff eligibility are independent. Use the stream bridge
or an HTTP service binding when a structured RPC value cannot fit the envelope; multipart selection
still follows server capabilities rather than serving as an RPC-size workaround. Do not claim
runtime Cloudflare-plan discovery.

{/* zhs-example: consumer-rpc-binding */}

```ts
import {
  createStashClient,
  StashHttpError,
  type StashRpcEntrypoint,
} from "@takazudo/zudo-history-stash";

export async function readThroughRpc(input: {
  binding: StashRpcEntrypoint;
  token: string;
  stash: string;
  path: string;
}) {
  const client = createStashClient({
    transport: { kind: "rpc", binding: input.binding, token: input.token },
  });

  try {
    const result = await client.files(input.stash).get(input.path);
    if (result.ok && "notModified" in result) {
      return { kind: "not-modified" as const };
    }
    if (!result.ok) {
      return { kind: "business-failure" as const, failure: result };
    }
    return { kind: "file" as const, value: result.value };
  } catch (error) {
    if (error instanceof StashHttpError && error.status === 0) {
      throw new Error("The RPC binding call was rejected before an HTTP response existed.", {
        cause: error,
      });
    }
    throw error;
  }
}
```

The named RPC surface intentionally excludes the live-event operation. Advisory SSE remains
fetch-only at `GET /v1/stashes/{stash}/events`; use an HTTP client or fetch service binding for it.
The generic binding `request()` method does not turn SSE into a named structured RPC method. See
[Live updates](./live-updates.mdx) for the stream lifecycle.
