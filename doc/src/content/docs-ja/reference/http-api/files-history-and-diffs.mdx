### `GET /v1/stashes/{stash}/files`

**Contract:** operation `listFiles`; principal `read`; transport `any`.

任意の tombstone、上限付きの `limit`、path keyset の `after` cursor とともに、ファイル summary を昇順で
一覧表示します。各 summary は head version、hash、size、deletion state、update time を報告します。

### `GET /v1/stashes/{stash}/files/{path}`

**Contract:** operation `getFile`; principal `read`; transport `any`.

head または正の履歴 `version` を読み取ります。読み取りに成功すると `ETag` と `X-Stash-Version` が含まれ、
`If-None-Match` によって body なしの `304` を返すことがあります。明示的に要求した tombstone は削除済みの
内容として返しますが、tombstone になっている head は `404 file-deleted` になります。

### `PUT /v1/stashes/{stash}/files/{path}`

**Contract:** operation `putFile`; principal `write`; transport `any`.

`expectedVersion` を使ってテキストを書き込みます。`null` は作成専用で、それ以外は現在の head と一致する
必要があります。通常の成功は version/hash/change metadata を含む `201` です。`skipIfUnchanged` では
履歴を追加せずに `200` を返すことがあります。冪等な replay は元の status を保持します。フェンスで負けると
`409 stale`、作成専用の場合は `409 exists` です。

### `POST /v1/stashes/{stash}/uploads/{path}`

**Contract:** operation `createUploadSession`; principal `write`; transport `fetch-only`.

宣言した representation、size、hash、expected head を検証した後、fence 付き raw upload session を作成します。
response はデプロイの capabilities から `single` または再開可能な `multipart` transfer を選び、D1 で bytes を予約してから
非公開 R2 に staging します。

### `GET /v1/stashes/{stash}/uploads/{sessionId}`

**Contract:** operation `getUploadSession`; principal `write`; transport `fetch-only`.

upload session の state、lease、宣言された content metadata、受理済み part の記録を返します。session の
recovery/status route であり、非公開 R2 object key は公開しません。

### `DELETE /v1/stashes/{stash}/uploads/{sessionId}`

**Contract:** operation `abortUploadSession`; principal `write`; transport `fetch-only`.

open な upload session を abort し、D1 の予約を解放し、staging 済みの R2 part を cleanup 対象にします。操作は
generation/lease で fence され、冪等性キーで安全に replay できます。

### `PUT /v1/stashes/{stash}/uploads/{sessionId}/content`

**Contract:** operation `uploadSingleContent`; principal `write`; transport `fetch-only`.

`single` session の正確な bytes を保存します。Worker は session の complete 前に宣言された byte 数と SHA-256 を
検証します。text と binary は別の representation として保持され、正しい UTF-8 は 5,000,000 byte を超えても text のままです。

### `PUT /v1/stashes/{stash}/uploads/{sessionId}/parts/{partNumber}`

**Contract:** operation `uploadPart`; principal `write`; transport `fetch-only`.

非公開 R2 に bounded multipart part を一つ upload します。part number と実際の byte length を session と照合し、
current generation には server が返した R2 ETag だけを記録します。同じ part の retry または replacement は bytes を
再 upload して durable record を置き換えます。client が指定する part hash や ETag manifest は受け付けません。

### `POST /v1/stashes/{stash}/uploads/{sessionId}/complete`

**Contract:** operation `completeUploadSession`; principal `write`; transport `fetch-only`.

single または multipart session を complete する前に全 bytes と SHA-256 を再検証します。generation/lease fence の下で
一つの immutable version を追加し、storage placement を記録して予約を解放します。同じ canonical request の complete replay は冪等です。

### `POST /v1/stashes/{stash}/uploads/{sessionId}/resume`

**Contract:** operation `resumeUploadSession`; principal `write`; transport `fetch-only`.

client または Worker の invocation 断後の recovery のため、利用可能な session の lease を更新します。宣言 content、
expected head、受理済み part は変更せず、expired または terminal session は閉じたままです。

raw upload は `text` または `binary` の bytes を変更せずに保持し、`single` または再開可能な `multipart`
transfer を選びます。選択肢は `/v1/capabilities` で確認できます。D1 で予約して非公開 R2 に staging し、generation/lease の
fence の下で complete してから version を追加します。5,000,000 byte を超えても binary とは限らず、正しい
UTF-8 は text のままです。complete は冪等性キーで replay でき、part の retry はその part number を再 upload/replacement
します。abort、expiry、lease recovery、GC も session lifecycle に含まれます。representation、access、transfer、storage、diff の独立した契約は
[ストレージ上限ガイド](../../guides/storage-tiers-and-limits.mdx)を参照してください。

### `GET /v1/stashes/{stash}/raw/{path}`

**Contract:** operation `getRawFile`; principal `read`; transport `fetch-only`.

現在の正確な bytes を `ETag`、`Content-Length`、`Content-Type`、`Accept-Ranges`、attachment-safe な
`Content-Disposition` とともに stream します。一つの satisfiable byte range、`If-Range`、`If-None-Match` に対応し、
非公開 R2 key は公開しません。削除済みの current head は空の byte stream ではなく metadata の結果として扱います。

### `HEAD /v1/stashes/{stash}/raw/{path}`

**Contract:** operation `headRawFile`; principal `read`; transport `fetch-only`.

current-file の `GET` と同じ raw representation headers を body なしで返します。length、media type、ETag、version、
range capability を確認でき、非公開 R2 key は公開しません。

### `GET /v1/stashes/{stash}/versions/{version}/raw/{path}`

**Contract:** operation `getRawVersion`; principal `read`; transport `fetch-only`.

指定した live historical version の正確な bytes を、current raw route と同じ range、conditional、attachment-safe headers と
ともに stream します。削除済みの履歴 version は空の byte stream ではなく metadata の結果として扱います。

### `HEAD /v1/stashes/{stash}/versions/{version}/raw/{path}`

**Contract:** operation `headRawVersion`; principal `read`; transport `fetch-only`.

指定した historical raw version の headers を body なしで返します。download 前に size、ETag、media type、range support を確認できます。

### `POST /v1/stashes/{stash}/delete/{path}`

**Contract:** operation `deleteFile`; principal `write`; transport `any`.

`expectedVersion` と任意の authorship を使用して tombstone を追加します。これは `POST` です。
intermediary が `DELETE` の request body を確実には保持しないためです。成功は `200`、tombstone の削除は
`409 already-deleted` です。

### `POST /v1/stashes/{stash}/rollback/{path}`

**Contract:** operation `rollbackFile`; principal `write`; transport `any`.

live な `toVersion` から、`expectedVersion` でフェンスした新しい version を追加します。`201` とともに
`rollbackOf` と、byte が古い head と一致したかどうかを返します。履歴を過去へ戻すことも、tombstone へ rollback する
こともありません。

### `GET /v1/stashes/{stash}/history/{path}`

**Contract:** operation `getHistory`; principal `read`; transport `any`.

metadata だけの version を新しい順で返します。現在の head、deletion state、total、`before` cursor が
含まれます。version の body は引き続きファイル読み取り route で取得します。

### `GET /v1/stashes/{stash}/diff/{path}`

**Contract:** operation `getDiff`; principal `read`; transport `any`.

必須の `from` と、正の `to` または `head` を比較します。任意の context と unified-output の上限が結果を
制限します。存在しない version とサーバー側 diff の失敗は、明示的なままです。

### `POST /v1/stashes/{stash}/diff/{path}`

**Contract:** operation `diffCandidate`; principal `read`; transport `any`.

提供された候補 body を version または head と、完全に memory 内で比較します。この read ケイパビリティの
POST は body、blob、version、変更を一切永続化せず、通常の上限付き diff model を返します。
