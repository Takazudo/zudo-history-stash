JSON の失敗は、機械可読な `error.code` が以下のいずれかの値になる、安定したエラー envelope を使います。
各操作に適用されるエラーは、route ページと OpenAPI ドキュメントで定義されます。

## Code/status contract

| Code | HTTP status | Meaning | Recovery |
| --- | ---: | --- | --- |
| `validation` | `400` | リクエストの形、query、値が無効です。 | 指定された field を修正してください。入力を変えずに再試行しないでください。 |
| `invalid-path` | `400` | ファイルパスが正規形でないか、パス規則に違反しています。 | 再試行の前にパスを正規化して検証してください。 |
| `body-not-well-formed` | `400` | テキストが well-formed content として受け入れられません。 | テキストの encode または内容を修正してください。 |
| `unauthorized` | `401` | 認証情報がない、無効、失効済み、または期限切れです。 | 現在有効な認証情報を取得し、もう一度認証してください。 |
| `scope` | `403` | 認証情報は有効ですが、必要なケイパビリティがありません。 | 適切な write/admin 認証情報を使用してください。read token の権限を広げないでください。 |
| `not-found` | `404` | 認可されたリソースが存在しないか、意図的に隠されています。 | 識別子と現在の principal を再確認してください。 |
| `file-deleted` | `404` | 現在のファイル head は tombstone です。 | 許可されている場合は、履歴を読むか新しい live version を作成してください。 |
| `version-not-found` | `404` | 要求した履歴上の version が存在しません。 | 履歴を更新し、存在する version を選択してください。 |
| `stale` | `409` | 期待した head が一致しなくなりました。 | 正本の head を再読み込みして照合し、その version で再試行してください。 |
| `exists` | `409` | 作成専用の操作で既存リソースが見つかりました。 | 既存リソースを読むか、更新用のフェンスを使用してください。 |
| `already-deleted` | `409` | ライフサイクルまたはファイルの削除が既存の tombstone を対象にしました。 | 削除済みとして扱うか、状態を更新してください。 |
| `commit-conflict` | `409` | atomic commit の entry が fence に失敗しました。 | `conflicts` を確認し、対象 path を更新して新しい commit として再試行してください。 |
| `gc-busy` | `409` | 別の世代がガベージコレクションのリースを所有しています。 | アクティブなリース期間の後で再試行してください。 |
| `already-rotated` | `409` | 前の token にはすでに後継があります。 | 後継 ID を確認してください。シークレットを失った場合は後継を失効させ、新しく作成してください。 |
| `token-expired` | `409` | ローテーション対象の前の token は期限切れです。 | admin 認証情報を使って新しい token を作成してください。 |
| `change-set-expired` | `409` | open change set が承認期限を過ぎました。 | 現在の head に対して新しい change set を作成してください。 |
| `change-set-closed` | `409` | change set の判断が終端状態と競合しています。 | change set を更新し、記録済みの判断に従ってください。 |
| `payload-too-large` | `413` | encode 済みリクエストまたは保存内容が上限を超えています。 | ドキュメント化された上限と単位に従ってリクエストを減らしてください。 |
| `idempotency-key-reused` | `422` | 一つのキーが別の正規リクエストに再利用されました。 | 新しいキーを生成してください。古いキーで再試行するリクエストを決して変更しないでください。 |
| `rollback-target-tombstone` | `422` | ロールバックで削除済みの履歴 version が選ばれました。 | live version を選ぶか、明示的な delete/create workflow を実行してください。 |
| `unsupported-representation` | `422` | 選択した transfer または content access mode では要求された bytes を表現できません。 | capabilities が示す raw text/binary upload と transfer mode を使用してください。 |
| `upload-size-mismatch` | `422` | 受信した bytes が session の宣言 size と一致しません。 | 宣言した byte 数を正確に送るか、新しい session を作成してください。 |
| `upload-hash-mismatch` | `422` | 受信した bytes が session の宣言 SHA-256 と一致しません。 | 正確な bytes で hash を再計算し、変更していない request を再試行してください。 |
| `range-not-satisfiable` | `416` | 要求した byte range が保存 content と重なりません。 | representation の length を更新し、satisfiable な range を要求してください。 |
| `upload-session-not-open` | `409` | upload 操作が terminal session を対象にしました。 | session state を読み、閉じていれば新しい upload を作成してください。 |
| `upload-session-expired` | `410` | upload session の lease と recovery window が期限切れです。 | 新しい session を開始し、期限切れ session への write を再試行しないでください。 |
| `rate-limited` | `429` | principal がリクエスト分類の予算を超えました。 | `Retry-After` に従い、backoff してください。 |
| `internal` | `500` | サーバーは操作を安全に完了できませんでした。 | リクエストの文脈を記録し、操作プロトコルで許可されている場合だけ再試行してください。 |

転送の失敗や不正なレスポンスでは、型付きエラー結果が存在する前に reject されることがあります。これらの
業務コードがないことから、成功を推測しないでください。
