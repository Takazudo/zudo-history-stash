管理者トークンと stash の書き込みトークンは、信頼できるサーバーまたは Worker のシークレットに
保持してください。Stash Worker を直接呼び出すブラウザには、有効期限付きで最小権限の読み取り
トークンだけを渡します。書き込みトークンは読み取り権限も持ち、その stash 内のすべてのパスを
置換、削除、ロールバックできます。管理者はすべての stash を操作できます。

トークンの作成とローテーションで平文のシークレットが公開されるのは一度だけです。シークレット
ストアへ直接渡して、ログには決して残さず、意図的にローテーションまたは失効させてください。
ライフサイクルの全体については、
[トークンの有効期限とレート制限](./tokens-expiry-and-rate-limits.mdx)を参照してください。

## 認証と存在秘匿

bearer トークンがない場合、不正な形式の場合、失効済みの場合、期限切れの場合は、すべて同じ
unauthorized 動作になります。有効な stash 認証情報で別の stash を問い合わせると、存在しない
データと同じ 404 形式が返り、その stash が存在するかどうかは開示されません。この存在秘匿を、
クライアント側の存在確認手段に変えてはいけません。

Service Binding はルーティング権限であって、アプリケーションの認証情報ではありません。Fetch と
RPC のどちらの Binding クライアントも、操作に必要な管理者トークンまたは stash トークンを提示する
必要があります。[Service Binding と RPC](./service-binding-and-rpc.mdx)で説明している認証境界を
維持してください。

## ブラウザ境界

ブラウザのオリジンは、Worker の `ALLOWED_ORIGINS` 設定にあるオリジンのいずれかと正確に一致する必要が
あります。preflight は開かれていますが、許可されていないオリジンには CORS の許可が返らず、
許可されたオリジンでも認証が必要です。CORS はブラウザのレスポンスポリシーであり、認可では
ありません。wildcard オリジンは allowlist の安全な代替になりません。

`clientId` は、助言的なライブ更新を抑制するために変更元を示すラベルにすぎません。提案の作成者と
メッセージのフィールド、UI の ID、コンシューマーが指定するその他の監査テキストにも権限はありません。
必須レビュー担当者、ロール、人間の ID 確認は、利用側アプリケーションが書き込み認証情報で承認する
前に実施する必要があります。

最後に、R2 オブジェクトのキーを公開したり、非公開バケットをダウンロードサービスとして扱ったり
してはいけません。コンシューマーは認証済み API を通じてバージョン管理されたテキストを読み、
その契約が返す正本のメタデータとハッシュを使用してください。
