`workers/stash/wrangler.toml` をデプロイ契約として扱ってください。その環境構成をコピーし、リソースの
プレースホルダーを置き換え、R2 バケットを非公開に保ちます。Cloudflare の環境では多くのバインディングと
変数のキーが継承されませんが、Durable Object の `migrations` は継承されます。継承されない各項目を
環境ごとに設定して検証します。すべてのキーを同じように扱うのではなく、選択した環境で継承される
マイグレーションの連鎖も検証してください。

## すべてのリソースをバインドする

| 種別 | バインディングまたはクラス | 用途 |
| --- | --- | --- |
| D1 | `DB` | stash、ファイル、バージョン、トークン、変更、提案の正本。 |
| 非公開 R2 | `BLOBS` | 退避されたファイル本文。オブジェクトキーと世代は公開 URL ではありません。 |
| Durable Object | `STASH_EVENTS` → `StashEvents` | stash ごとの同期的なライブイベントのファンアウト。 |
| レートリミッター | `RL_READ` | 読み取りルートの分類。 |
| レートリミッター | `RL_WRITE` | 変更ルートの分類。 |
| レートリミッター | `RL_DIFF` | 差分ルートの分類。 |

`STASH_ADMIN_TOKEN` は通常の `[vars]` の値ではなく、必ず Worker シークレットとして設定してください。
平文はパスワードマネージャーまたは CI のシークレットストアから Wrangler のシークレット入力へ直接渡し、
コマンド履歴とログに残さないでください。

検証済みの変数と、コミット済みのデフォルト値は次のとおりです。

| 変数 | デフォルト値と単位 |
| --- | --- |
| `ALLOWED_ORIGINS` | 空の許可リスト。意図したブラウザーのオリジンを明示的に設定します。 |
| `STASH_DELETE_GRACE_DAYS` | `30` 日。 |
| `GC_ORPHAN_MIN_AGE_MS` | `900000` ミリ秒。 |
| `GC_LEASE_TTL_MS` | `300000` ミリ秒。 |
| `PROPOSAL_TTL_DAYS` | `14` 日。 |
| `STASH_EVENTS_MAX_STREAM_MS` | `300000` ミリ秒。 |

`workers/stash/src/env.ts` が受け付ける正確な名前と単位を使ってください。名前を変更した変数や単位を
換算した変数は同等ではありません。

## 二つの異なるマイグレーション系列を適用する

D1 スキーマのマイグレーションは `workers/stash/migrations` にあり、現在は `0001_init.sql` から
`0004_proposals.sql` まで順番に実行します。アプリケーションをデプロイする前に、選択したリモートの
`DB` へ適用してください。

Wrangler の `[[migrations]]` にある `v1` タグの項目は別物であり、SQLite ベースの `StashEvents`
Durable Object クラスを登録します。そのマイグレーションと対応するバインディングを、デプロイするすべての
環境に維持してください。これは D1 SQL の系列を置き換えるものではなく、イベントオブジェクトが履歴の
正本ストアになるわけでもありません。

## 検証可能な順序でデプロイする

環境ごとに、次の手順を実行します。

1. D1 と非公開 R2 を準備し、その正確な ID または名前を解決します。
2. D1、R2、Durable Object、レートリミッター、変数、ルート、トリガーの全項目を設定します。
3. 選択した Wrangler 設定で D1 マイグレーションをリモートに適用します。
4. 保護されたシークレット入力から `STASH_ADMIN_TOKEN` を設定します。
5. 同じ設定を使って Worker をデプロイします。
6. 意図したオリジンに対して、読み取り専用のヘルスチェックと、認証済みのプリンシパルおよび読み取り検査を行います。

本番環境では `17 3 * * *` にガベージコレクションをスケジュールします。コミット済みのプレビュー環境と、
PR ごとに生成するアプリケーション設定では、cron の一覧を空にします。本番用トリガーをコピーして、
使い捨てのプレビューストレージに対して実行しないでください。

Wrangler の環境モデルでは、`vars`、Durable Object バインディング、D1、R2、そのほかのバインディングは
継承されません。Durable Object の `migrations` は継承されますが、このリポジトリではクラス登録を
明示したままにするため、検査対象のプレビュー設定にも同一の `v1` 項目を繰り返しています。デプロイ前に、
選択した環境を一つの完全な単位として比較してください。Cloudflare の最新の
[環境](https://developers.cloudflare.com/workers/wrangler/environments/)および
[設定](https://developers.cloudflare.com/workers/wrangler/configuration/)リファレンスも参照してください。

## 公開範囲と課金対象を限定する

`BLOBS` を非公開に保ち、R2 キー、世代、ドキュメント本文、Bearer トークンをログに残さないでください。
ライブイベントストリームではレスポンスを処理している間、ハイバネーションしない Durable Object が
アクティブなままになります。設定したストリーム有効期間と認証済みトークンの有効期限によって接続が
ローテーションされ、再接続と失効が反映されますが、アクティブなリクエスト、実行時間、ストレージ、操作は
引き続き課金対象になり得ます。利用中のアカウントについて、最新の
[Durable Objects](https://developers.cloudflare.com/durable-objects/)、
[D1](https://developers.cloudflare.com/d1/)、[R2](https://developers.cloudflare.com/r2/)、
[Workers の料金](https://developers.cloudflare.com/workers/platform/pricing/)を確認してください。一律の
無料枠、費用ゼロ、ハイバネーション、即時のクリーンアップを前提にしてはなりません。

Cloudflare の[シークレットガイド](https://developers.cloudflare.com/workers/configuration/secrets/)では、
暗号化されたシークレットバインディングと CI で安全に使える入力方法を説明しています。この Worker では、
リポジトリ内の検査対象設定とデプロイワークフローが引き続き正本です。
