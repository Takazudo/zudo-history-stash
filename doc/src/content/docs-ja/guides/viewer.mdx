Viewer は、Stash Worker を操作するための信頼済みインターフェースです。インターネットに公開する場合は
Cloudflare Access または同等の境界の内側に配置しつつ、API の Bearer トークンとスコープの検査も
維持してください。外側の境界、ルートの可視性、非表示のコントロールはいずれも認可にはなりません。

## プリンシパルをまたがずにサインインする

ログインフォームは、Bearer トークンを有効にする前に `/v1/me` で検証します。トークンはこのブラウザータブの
`sessionStorage` に保持されます。URL、ログ、分析イベント、スクリーンショット、サポート用の記録、
フィクスチャ、ビルド成果物には含めないでください。安定したタブクライアント ID は、変更リクエストに
発生元および監査用のメタデータとして付与されますが、認証情報ではありません。

認証情報を置き換えるときは、まず候補を検証し、次に認証情報に紐づくワークベンチのドラフトを消去し、
タブストレージへの保存を確認してから、新しいプリンシパルを有効にします。消去または保存に失敗したら
処理を止め、そのタブで別のプリンシパルとしてサインインしないでください。ログアウト時と `401` 後の
自動ログアウト時には、常にメモリ内のクライアントを無効にします。保存データを消去できなかったという
警告が Viewer に表示された場合は、再びサインインする前にタブを閉じ、サイトデータを消去してください。

ケイパビリティは解決済みの `/v1/me` プリンシパルから得られ、そのプリンシパルの読み込み中または
切り替え中はフェイルクローズになります。

| ケイパビリティ | Viewer での操作 |
| --- | --- |
| 読み取り | stash とファイルの閲覧、履歴、commit、change set、差分の確認。 |
| 書き込み | ファイルの作成、編集、削除、復元、rollback、レビュー単位の承認、却下、revert。 |
| 管理者 | stash の作成、削除、復元、トークンの管理、およびガベージコレクションの実行。 |

## Viewer のルート

Viewer の URL はナビゲーション状態であり、アクセス権の証明ではありません。

| ルート | 用途とクエリ |
| --- | --- |
| `/login` | このタブで使う認証情報を検証し、有効にします。 |
| `/` | 現在のプリンシパルから見える stash を一覧表示します。 |
| `/s/:stash` | 一つの stash とそのファイルを表示します。 |
| `/s/:stash/f/*` | ファイルを表示します。`?version=N` を指定すると履歴上のバージョンを選択します。 |
| `/s/:stash/diff/*` | `?from=N&to=M&context=N` で指定したバージョンを比較します。現在の head を使う場合は `to=head` を指定します。 |
| `/s/:stash/edit/*` | ファイルを編集します。任意の `?from=N` で読み込むソースバージョンを固定します。 |
| `/s/:stash/new` | ファイルを作成します。 |
| `/s/:stash/commits` | commit を一覧表示し、任意で path により絞り込みます。 |
| `/s/:stash/commits/:id` | 一つの commit と entry ごとの diff を確認します。書き込み権限があれば revert できます。 |
| `/s/:stash/change-sets` | レビュー候補を status または path で一覧表示します。 |
| `/s/:stash/change-sets/:id` | candidate の diff と staleness をレビューします。書き込み権限があれば approve/reject できます。 |
| `/s/:stash/tokens` | 管理者専用のトークン管理です。 |

commit と change-set のページは、複数パスの操作を一つのまとまりとして扱います。commit detail は上限付きの
entry ごとの diff を展開し、各パスの file history へ link します。revert は別のアトミック commit を作成する
ものであり、表示中の record を削除しません。対象 head が一つでも進んでいる場合、Viewer はサーバーから
返された entry ごとの競合を表示し、残りだけを再試行することはありません。

change-set review では、記録済み base と不変 candidate を entry ごとに比較し、stale entry を明示します。
aggregate stale notice は decision request を実行するまで助言にすぎません。approve は全 fence を再検査するため、
その間の競合で失敗することがあります。競合時は正本の record を再取得し、現在の head に対する解決後に新しい
change set を作成してください。applied、rejected、expired の record は不変な decision history として残り、
編集や reopen はできません。

## バイナリの upload と raw download

新規ファイルのルートには、テキストエディターと capabilities 駆動の raw upload form があります。
representation（`text` または `binary`）、content access（`inline`、`raw`、`deleted`）、transfer
（`json`、`single`、`multipart`）、storage（`d1`、`r2`）、diff eligibility は独立しています。
5,000,000 バイトを超えても自動的に binary にはなりません。raw API で送った正しい UTF-8 は `text` のままです。
form はサーバーの single-upload 上限までは一つの request、それを超えると再開可能な multipart を使います。
compare-and-set の head が stale の場合は競合として表示します。

ファイルページが preview するのは、上限付きの UTF-8 text と許可リストにある PNG/JPEG/WebP/GIF の raster
画像だけです。それ以外の binary と大きすぎる text は download 専用で、active content は埋め込みません。
履歴の raw link は選択した version を保持し、削除済み version は空ファイルとして黙って表示せず metadata を
表示します。

大きな認証済み download では、File System Access に対応するブラウザーは response を選択したファイルへ
直接 stream します。未対応ブラウザーは Blob にバッファリングせず、**32 MiB（33,554,432 bytes）を超える
raw download を意図的に拒否**します。download がキャンセルまたは失敗した場合はファイルページから再試行するか、
上限付き range または信頼できる外部 client を使ってください。bearer token を URL に入れてはいけません。
復旧や比較では、表示された version、size、hash、ETag を確認してください。

## 読み込み時の head をフェンスとして編集する

保存時には、ドラフトとともに読み込んだ head を compare-and-set のフェンスとして使います。別の書き込み元が
head を進めると、Viewer は未保存のテキストと固定された比較対象を保持したまま、ドラフトを
stale（古い状態または競合）としてマークします。正本のバージョンを再読み込みして比較し、変更を意図的に
適用し直してください。stale なドラフトを闇雲に再試行したり、自動的にマージまたはリベースしたりしては
なりません。

トークンの平文は発行直後に一度だけ表示されます。意図したシークレットストアへ直接移し、そのページから
離れてください。後から一覧でメタデータを確認することはできますが、認証情報は復元できません。

## ライブ状態をヒントとして読み取り、正本と調整する

ステータスインジケーターでは、次の四つのラベルを使います。

- `Live`: イベントストリームに接続しています。
- `Reconnecting`: ストリームを復旧しています。
- `Polling`: 正常なストリームがない状態でも、正本となる再取得を続けています。
- `Off`: ライブ更新を利用できないか、無効にしています。

イベントの発生元とパスはヒントです。Viewer は、フォーカスまたは可視性の変化後も含め、正本となる
変更フィードまたは再取得で調整してから状態を採用します。内部のポーリング間隔やストレージキーの表記に
依存する運用手順を作らないでください。

安全な診断については、[トラブルシューティング](./troubleshooting.mdx)へ進んでください。
[リファレンスのランディングページ](../reference/index.mdx)は、API とエラーの網羅的な契約を確認するための
安定した入口です。
