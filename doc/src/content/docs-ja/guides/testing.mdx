テストの証跡は積み重ねです。高速なフェイクは決定論的なクライアント動作を証明しますが、ネットワーク、
Worker バインディング、ブラウザー、デプロイ済みプラットフォームは証明しません。最初に失敗した結果と
その修正を記録してください。再試行が成功しても、最初の結果が消えることはありません。

## 証跡レベル

| レベル | 証跡 |
| --- | --- |
| L1 ユニット | 純粋なバリデーター、スキーマ、ハッシュ、SDK の動作、決定論的なヘルパー。 |
| L2 DOM/コンポーネント | Testing Library と制御されたクライアントを使った React コンポーネントおよびルート。 |
| L3 ビルド/静的 | パッケージバンドル、生成アセット、Worker のドライラン、`publint`、`attw`。 |
| L4 ブラウザー | Playwright による Chromium のナビゲーションと操作。 |
| L5 ライブ/インフラストラクチャ | 実行中の Workers、D1/R2/DO バインディング、サービスのプロキシ、SSE、デプロイ済みのスモーク。 |

ローカルの `pnpm b4push` は T0 のリポジトリゲートです。固定された依存関係との整合、ライブラリのビルド、
フォーマット、型、lint、ユニットテスト、アプリケーションのビルド、検査対象 Worker のドライランを
実行します。CI は T1 であり、パッケージ公開の検査とブラウザー処理を追加します。T0 は、サーバーを伴う
HTTP 契約、チェックイン済みのライブ SDK 適合性検査、保護されたモック/ライブのブラウザーレーン、
デプロイ済みの Pull Request プレビューレーンを開始しません。これらが受け入れ証跡になる場合は、個別に
記録してください。

開発中は対象パッケージのテストと型検査を使い、統合時にはルートゲートを実行します。Docs の変更には、
集約された単一の入口として `pnpm b4push:doc` があります。その内部ステージは Docs のツール群が所有するため、
別のチェックリストへコピーしないでください。

## ローカルのフルスタック構成

`pnpm dev:full` はライブラリと Viewer アセットをビルドし、ローカル D1 マイグレーションを適用して、Viewer を
`http://localhost:8787` で起動します。`/api` 以下のリクエストは Stash Worker へ到達し、同じ Wrangler
ランタイム内の `STASH` service binding を通ります。ローカルの D1、R2、SQLite ベースの `StashEvents`
Durable Object は、ワークツリー内に永続化された Wrangler 状態を使います。シードと契約のコマンドは、別の
Stash ポートを仮定せず、`http://localhost:8787/api` を通します。

シードは既知の `demo` フィクスチャを作成します。破壊的な契約テストと適合性検査では、分離した名前を作成し、
ループバック内だけで実行しなければなりません。手動で管理する `dev:full` プロセスと、一つのコマンドで
動かすライブブラウザーレーンが、同じポートまたは永続化された状態を奪い合わないようにします。

## 環境の安全性マトリックス

| 環境 | 許可される変更 |
| --- | --- |
| 分離されたローカル | ワークツリー内のローカルリソースに限り、CRUD 全体、障害注入、シード、破棄を行えます。 |
| Pull Request ごとのアプリケーションプレビュー | ワークフローが明示的に使い捨てとして行うプロビジョニングと `demo` シードのみ。その後は読み取りの証跡だけを取得します。 |
| 共有プレビューまたはステージング | 別途レビュー済みの使い捨て名前空間とクリーンアップ契約がない限り、読み取り専用です。 |
| 本番 | 読み取り専用のヘルス、プリンシパル、既知の正常な読み取り。変更またはライブ適合性検査の準備は決して実行しません。 |

認証情報は無視対象のローカルファイルまたは CI のシークレットストアに置き、フィクスチャ、スナップショット、
Docs の出力、スクリーンショット、成果物には含めないでください。ブラウザーとインフラストラクチャの
コマンドは、引き続きガードの下で実行します。成功結果を得るためだけに、ループバック、層、URL、トークンの
前提条件を弱めてはなりません。

## 各ライブレーンが証明する範囲を把握する

HTTP 契約はすべての層で、ヘルス、認証、読み取り、履歴、差分、変更、上限付きの SSE-ready ハンドシェイクを
検証します。永続化するケースは、ループバックのローカル層でだけ実行します。SDK のライブ適合性ランナーも
変更を伴い、ループバック限定です。Worker/RPC テストは分離されたバインディングと通信方式の同等性を
検証しますが、デプロイ済みオリジンを証明したとは主張しません。

モックブラウザーテストは、ルーティングしたレスポンスを使って UI の動作を証明します。保護された
ライブブラウザーテストは、ローカルの Viewer、service binding、ストレージ、SSE の組み合わせを証明します。
Pull Request プレビューのブラウザー証跡は、生成した読み取りトークンを使い、実際の HTTPS 上で実行する
正確に一つの `@preview` テストです。モックを使わず、コンソールを厳格に検査し、書き込み操作は提供しません。
必要な URL またはトークン入力が存在しないか不正な場合は、成功扱いでスキップせず、テスト収集より前に
失敗します。

現在のコマンドと構成については、リポジトリの `TESTING.md` を参照してください。第二の正本を作るのではなく、
新しいテストを、環境を層分けする既存パターンと Vitest のパターンに合わせてください。
