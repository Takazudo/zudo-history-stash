Zudo History Stash は、バージョン管理された UTF-8 テキストとバイト列を変更しないバイナリを
Cloudflare Workers 上で扱う、Git の考え方を取り入れた小規模なストアです。各パスに追記専用の履歴、
明示的な compare-and-set 書き込み、保存済み内容と候補内容の diff、新しいバージョンとしての
ロールバック、提案を介したコンシューマー所有の承認、助言的なライブ更新シグナルを提供します。
Git ホスティングでも、汎用ファイルシステムでもありません。

アプリケーションは Stash Worker を呼び出します。D1 は stash のメタデータ、ファイルの head、履歴、
inline bytes の正本です。大きな不変 bytes は、非公開かつコンテンツアドレス方式の R2 バケットに保存
されます。representation（`text` または `binary`）、content access（`inline`、`raw`、`deleted`）、
transfer（`json`、`single`、`multipart`）、storage（`d1`、`r2`）、diff eligibility は独立しています。
正しい UTF-8 本文は 5,000,000 バイトを超えても `text` のままであり、サイズから representation を
推測しません。別途デプロイした Viewer は、認証済み Service Binding を通じて Stash Worker に接続します。
R2 が公開オブジェクト API になることはありません。

## 適した用途

History Stash は、サービスがパスごとの履歴や監査証跡を必要とする場合、呼び出し側が並行書き込みを
フェンスする必要がある場合、レビュー担当者が不変の候補 diff を必要とする場合、または助言的な
変更イベントの後にインターフェースを更新したい場合に適しています。

複数ファイルにまたがるアトミックコミット、ブランチとマージ、組み込みのレビュー担当者ロールや
レビューコメントが必要な場合は、別のシステムを選んでください。History Stash はバイナリとバイト範囲
配信をサポートしますが、Viewer がプレビューするのは上限付きテキストと許可リストの raster 画像だけです。
未対応ブラウザーはバッファリングせず、32 MiB を超える raw download を意図的に拒否します。承認ポリシーと
ユーザー ID は、引き続き利用側アプリケーションの責任です。
